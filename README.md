# 테트리스 역추적(Backtracking) 탐색 시각화

> **생활 속 알고리즘, 생성형 AI로 풀다** — 정해진 순서의 블록으로 보드를 완전히
> 비우는(**Perfect Clear**) 퍼즐을, 백트래킹 알고리즘이 풀어가는 **전체 탐색
> 과정을 실시간으로 재생하고 배속을 조절**하며 관찰하는 교육용 웹 서비스.

## 3. 핵심 자료구조

| 자료구조 | 구현 | 설명 |
|---|---|---|
| **보드판** (2D Grid Array) | `board[row][col]` | `0`=빈칸, `N(≥1)`=N번째로 안착한 블록(순서 번호 각인), `-1`=가비지 |
| **블록 대기열** (Queue) | `stage["queue"]` | 스테이지별 고정 순서의 블록 리스트(FIFO) |
| **탐색 히스토리 로그** | `solver.history` | `try`/`prune`/`backtrack`/`solution`/`clear` 이벤트와 보드 스냅숏의 타임라인 |

## 4. 알고리즘 설계

### (1) 물리 낙하 기반 백트래킹
1. **블록 선택** — 큐에서 N번째 블록을 꺼낸다.
2. **낙하 시뮬레이션** — 모든 열(0~W-1)과 회전(0°·90°·180°·270°, 중복 제거)
   조합을 순회하며 위에서 직선 낙하해 안착 행을 계산한다.
3. **상태 기록·재귀** — 블록을 안착시키고(순서 번호 N 각인) 스냅숏을 히스토리에
   기록한 뒤 N+1번째 블록으로 재귀.
4. **역추적** — 막다른 길이면 블록을 회수하고 다음 위치/회전 조합을 시도한다.

> **탐색 모델 주의**: 본 구현은 "보드를 빈틈없이 가득 채우면 모든 줄이 한꺼번에
> 사라져 비워지는" **타일링 모델**로 탐색한다(중간 줄 제거를 미룸). 덕분에 아래
> 가지치기들이 *정답 경로를 절대 잘라내지 않음(safe)* 이 보장되며, 줄 제거는
> 마지막에 연출된다. `verify_stages.py` 가 모든 스테이지에 대해
> **가지치기 ON 노드 수 ≤ OFF 노드 수**(안전성)와 풀이 가능성을 검증한다.

### (2) 조합 폭발 방지: 플러드 필(BFS) 가지치기
블록을 하나 놓을 때마다 빈 공간을 BFS로 분석한다.
- **`fragment`** — 분할된 빈 공간 영역의 칸 수가 **블록 크기(4)로 나눠떨어지지
  않으면** 그 영역은 절대 채울 수 없으므로 즉시 역추적.
- **`sealed`** — 위가 막혀 낙하로는 도달할 수 없는 **봉인된 빈 칸**이 생기면 역추적.

실제 효과(예: `5. 가지치기 데모 · T 블록 4개`): 탐색 노드 **44 → 22 (50% 감축)**.
`6열 심화` 스테이지에서는 **159 → 68**. UI 우측 *탐색 통계* 패널에서 ON/OFF를
실시간 비교한다.

## 5. 주요 기능

### ① 직접 플레이 모드 🎮
고정된 블록 순서를 보며 직접 퍼펙트 클리어에 도전.
`← →` 이동 · `↑` 회전 · `Space`/`↓` 내려놓기 (버튼도 지원).

### ② AI 실시간 탐색 시각화 🤖 (핵심)
- **`▶ 탐색 시작`** : 백트래킹 전 과정을 재생.
  - **시도(trying)** → 일반 색 / **역추적·가지치기** → 블록과 보드 테두리가 **빨강**.
  - **정답/퍼펙트 클리어** → **초록** 강조 + 플래시 연출.
- **`🏁 정답만 재생`** : 정답 배치를 순서대로 보여주며 **1, 2, 3… 순서 번호 각인**
  후 전체 줄 제거.
- `8. (보너스) 해 없음` 스테이지는 백트래킹이 **모든 경우를 시도한 뒤 '해 없음'을
  선언**하는 과정을 시연.

### ③ 실시간 배속 제어
배속 슬라이더(**0.5x ~ 4.0x**)가 재생기의 `setInterval` 대기 시간(ms)과 실시간으로
연동된다. 단계 이동(◀ ▶▶), 처음으로(⏮), 타임라인 스크러버도 제공.

## 6. REST API

| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/api/pieces` | 7종 블록의 색상·회전 메타데이터 |
| `GET` | `/api/stages` | 스테이지 목록(보드 크기·큐·가비지) |
| `POST` | `/api/solve` | `{stage_id, pruning}` → 탐색 히스토리·정답·통계 |
| `POST` | `/api/register` · `/api/login` · `/api/logout` | 계정 생성/로그인/로그아웃(세션 쿠키) |
| `GET` | `/api/me` | 현재 로그인 사용자(세션 복원) |
| `GET` | `/api/records` | 현재 사용자의 스테이지 기록 전체 |
| `POST` | `/api/records/attempt` · `/clear` · `/hint` · `/reset` | 시도 +1 / 클리어 고정 / 힌트 표시 / 초기화 |

> **기록 규칙** — 시도 횟수는 클리어 못 한 한 판마다 +1(실패·재시작 포함)로 누적되고,
> 클리어하는 판까지 센 뒤 **고정**된다. AI 탐색/정답 재생을 본 스테이지는 **힌트 사용**으로
> 표시되며 클리어로는 기록되지 않는다. 모든 기록은 `tetris.db` 에 **아이디별로** 저장된다.

> **스테이지 선택** — 1~50번을 페이지당 10개씩 5페이지로 배치하고, 페이지 상단의 별 1~5개로
> 난이도를 나타낸다. 화면 중앙 좌/우 화살표로 페이지(난이도)를 바꾼다. 아직 만들지 않은
> 번호는 `준비 중` 잠금으로 표시되며, 스테이지를 추가하면 자동으로 채워진다.

`/api/solve` 응답 예:
```json
{
  "solved": true,
  "width": 4, "height": 4, "queue": ["T","T","T","T"],
  "history": [ { "type": "try", "board": [[...]], "active": [[r,c]...],
                "piece": "T", "order": 1, "depth": 0, "msg": "..." }, ... ],
  "solution": [ { "piece": "T", "rotation": 0, "col": 0, "row": 2,
                  "order": 1, "cells": [[r,c]...] }, ... ],
  "stats": { "nodes": 22, "backtracks": 4, "prunes": 14, "events": 42 }
}
```
